# Numbering

Generated document numbers, client numbers and resource codes, in each company's own format (Paramètres > Numérotation).

Moved out of CLAUDE.md on 2026-11-26 - keep it up to date in the same commit as the code it describes.

## Backend

- **Document numbers are server-generated**: `document.service.ts`'s `generateDocumentNumber`, in the company's own format - **Paramètres > Numérotation** (since 2026-11-18, `/settings/numbering`, the `numbering` table - `022_add_document_numbering.sql`, renamed by `024_add_client_resource_numbering.sql` which added CLIENT/MATERIAL/SERVICE - one row per company + QUOTE/INVOICE/CLIENT/MATERIAL/SERVICE, `modules/numbering` - `GET /numbering`, `POST /:type/preview` (the page's live preview, nothing written), `PUT /:type` an ADMIN/PLATFORM_ADMIN's only): a format of literal text (letters, digits, `- _ . /`), `{YYYY}`/`{YY}` and exactly one `{N...}` sequence padded to its N count (`shared/numbering/number-format.ts`, tested - a 400 `NUMBER_FORMAT_<reason>` otherwise, `NUMBER_FORMAT_TAKEN` for a format reading the numbers of another type sharing its table, or read by it - quote/invoice/chantier, material/service: `F{NNNN}` and `F{NNNNN}`, `D{NNNN}` and `D{YY}{NNNN}` (`formatsOverlap`)), and an optional start number - a company moving to Docky continues its series - only for the year it was set when the format has the year (a start saved again unchanged keeps that year - the page only sends the types changed anyway; the sequence restarts at 1 every year then; without the year it never does). No row: `OFF-{YYYY}-{NNNN}` / `FAC-{YYYY}-{NNNN}`, every number given out before; a chantier's PROJECT document always `CH-{YYYY}-{NNNN}`. The next number is one past the highest already given out with that format this year (`getHighestSequenceFromDB`, the format's anchored `numberPattern` through Postgres' `~`/`substring`, any type, archived included - a sequence of 15 digits at most), at least the start, skipping one another format happened to give out (`isDocumentNumberTakenInDB`) - not a counter table (see [zz_docs/Decisions.md](../Decisions.md) for why) - backed by `UNIQUE (company_id, number)`. `POST /document` ignores any client-supplied `number`. Under one advisory lock per company (`lockDocumentNumberingInDB`, `pg_advisory_xact_lock` - formats being the company's own, two could produce the same number) held until the transaction inserting the document commits - so `generateDocumentNumber` is only ever called inside `withTransaction`, the insert in the same one. `addDocumentServ` takes it before its "already invoiced" check, so two invoices for one chantier created at once take turns too. The QR-bill's payment references take the number's digits/letters (`payment-reference.ts`), whatever the format. The weekly demo reset deletes company 2's row. Tested: `numbering.test.ts` (formats, start, never below a number given out, concurrent creations, roles, tenants, clients and resources, an import).
- **Client numbers and resource codes are server-generated**, in the company's own format like document numbers (since 2026-11-19 - **Paramètres > Numérotation**'s CLIENT/MATERIAL/SERVICE, see the document numbers bullet above): `C0001`, `C0002`... and `MAT0001` / `SER0001`... by default, per company, whatever the request says (`POST /client` and `POST /resource` drop a `client_number`/`code` from the body; `PUT /resource` can't change a code either). `numbering.service.ts`'s `nextNumberServ`, the same rule as documents (the highest matching the format plus one - `getHighestClientSequenceFromDB`/`getHighestResourceSequenceFromDB`, archived rows included, never handed out twice - at least the start, skipping one already taken), under a per company advisory lock inside the creating transaction (`lockClientNumberingInDB`, `lockResourceCodingInDB` - one for materials and services together). A material's and a service's format can't be the same. Codes typed by hand before this (`APPR-1`, `MAT101`) stay as they are, a non-matching one ignored. A material resource also has an optional free **`reference`** (`015_add_resource_reference.sql`, 50 chars, not unique - e.g. a supplier's article number; a service has none - `resource.service.ts` stores null for one, the form and the services list don't show it), shown in the resource list/form and under a document line's label when the line comes from that resource (not printed on the PDFs yet).
