# Test coverage

What the unit tests cover, file by file. How to write tests stays in CLAUDE.md.

Moved out of CLAUDE.md on 2026-11-26 - keep it up to date in the same commit as the code it describes.

## Unit tests

- Existing coverage: backend `document.calculations.ts` (totals, `lineTotal`), `pdf/templates/placeholders.ts` + `document.placeholders.ts` + `pdf-labels.ts` (placeholders, PDF language and dates), `reminder.placeholders.ts`, `dto/reminder.dto.ts` (a final invoice's reminder asking its balance); frontend `display.ts`, `document-draft.ts`, `document-status.ts`, `document-scan-match.ts`, `api-error.ts`, `note-time.ts`, `postal-code-search.ts`, `invoicing-readiness.ts`, `import-columns.ts`; backend `modules/permissions/permissions.ts`, `pdf/templates/format.ts`, `swiss-qr-bill.payload.ts` (with the QR-bill's validators), `swiss-qr-bill.dto.ts`, `payment-reference.ts`, `shared/numbering/number-format.ts`, `shared/address/postal-code-city.ts`, `accent-color.ts`, `element-colors.ts`, `payment-scale.ts`, `rich-text.ts` (both sides), `service-period.ts` (both sides), `template.rules.ts`, `template.sample.ts`, `reminder.rules.ts`, `billed-address.ts`, `client-import.ts`, `color-elements.ts`, `deposit.ts`, `error_log.fingerprint.ts`, `error_log.notification.ts` — each with a colocated `*.test.ts` (plus `app.spec.ts` and a scaffold-style `client-form.spec.ts`). `api-error.test.ts` is the one async exception to "nothing async" (reading a Blob body) - still a pure function, no I/O. Don't assume anything else has coverage. All pass (238 backend unit, 126 backend integration, 119 frontend as of 2026-11-26), and CI (see Deployment) runs all three before deploying. Not covered by an integration test yet: PDFs, file uploads (MinIO), the dashboard, the calendar.

## Integration tests

- Cover so far: login/refresh/roles (`auth.test.ts`), cross-company access by id (`tenant-isolation.test.ts`), accepting a quote into a chantier, concurrent accepts included (`quote-to-project.test.ts`), saving a document's content - totals, validation, rollback, concurrent saves past the pool's size (`document-content.test.ts`) - an invoice's lifecycle, numbering and invoicing a chantier once, concurrent creations included (`invoice-lifecycle.test.ts`) - creating a client without an email or with its address (`client-creation.test.ts`) - document templates: defaults, rules, documents given one, the discount on a change, a sent document's frozen look, tenants and roles (`templates.test.ts`) - generated client numbers and resource codes, concurrent creations included (`generated-codes.test.ts`) - importing clients, all or none, numbering and 1000 rows (`client-import.test.ts`) - the address a quote/invoice is frozen with once sent (`billed-address.test.ts`) - payment references frozen when an invoice is sent and the company's QR-IBAN (`payment-reference.test.ts`) - and a template's every layout and font printed (`document-style.test.ts`) - employee permissions: hidden and read-only modules, filtered lists, the admin and other companies unbound (`employee-permissions.test.ts`) - and deposit invoices and the final invoice deducting them: percentage or amount, numbering, the chantier's summary, a chantier without a quote, tenant isolation, the balance, a draft deposit blocking the final invoice, frozen deductions and a deducted deposit that can't be cancelled, the dashboard's amount (`deposit-invoice.test.ts`) - and an invoice's service period (`service-period.test.ts`) - and payment reminders: levels and their admin, sent in order once due, fees, invoices to remind, printing a sent one, taking back the latest, tenants (`reminders.test.ts`).
